# 空中指挥原型

机场指令由指挥官AI理解、核对后，直接以塔台身份向飞机发令，飞行员向塔台复诵执行；不额外播报玩家转述。管制方仅在飞机状态卡右侧显示，交接方式自动跟随设置中的严苛／宽松模式，不另设大模块或模式选择。严苛模式从电台或教程手动请求，宽松模式自动交接；通知转接、复诵告别、向接收方报到、确认接管全部播报后才切换。返场先交回塔台。第二关练习离场交接，第三关练习返场交接；详见[管制交接](../docs/control-handoff.txt)。

机场通联会核对当前机位、飞行阶段和事件时效，飞机升空后不再播报旧的“机位准备就绪”或滑行许可；读档保留机场历史供查阅，但不自动重新播报。新场景的实际地面就绪和新产生的有效通联照常播报。

顶部“告警”打开简化RWR：搜索辐射只报告，持续跟踪默认等待8秒、疑似发射等待4秒，未收到玩家新指令才自主规避。玩家新指令优先，可切换“只报告”并调整等待时间；规避保留原任务，接收不依赖本机搜索雷达是否开启。详见[雷达告警与自卫](../docs/rwr-defense.md)。

进入“航线设置”会自动进入专注编辑：地图铺满视口，只保留飞机、航路和光标预览，暂时收起指挥、简报、教学、状态卡、字幕及工具栏，屏蔽隐藏界面的鼠标与键盘焦点。按Esc退出，恢复进入前打开的窗口、位置、大小及滚动位置；不会覆盖保存的布局。编辑期间航路语音仍正常播报。

顶部“武器”打开实时导弹面板。F-16 默认采用五类各两枚的混合演练挂载，可比较红外、半主动雷达、主动雷达引导；准备后明确发射，三维弹道和速度/推力/过载随物理更新。目录内24个变体可在“导弹演练配置”补装。雷达弹先锁定目标，红外弹指定可见目标并准备；发射不等于命中，交战规则不自动发射。详见[实时导弹与引导](../docs/missile-simulation.md)。

窗口可以拖动四边及四角调整大小，松开后连同位置保存；首次打开会优先避开飞机和航路，手动保存的布局不被自动覆盖。“设置 → 工具与帮助 → 窗口避让飞机与航路”可按当前画面重新安排已打开的窗口。

地图航点输入统一受“航线设置”开关控制。未打开时不能放点、拖点或撤销航路编辑。打开后，从飞机按住左键拖动可手绘航路，自动提取转折航点并识别直线；普通右键单击替换整条航路，按住CapsLock＋右键单击连续追加；空白处单击左键不放点。在航点按住左键可拖动，Alt＋拖动只改高度。光标旁实时预览海拔、离地高度和吸附状态，滚轮调整空间深度，手绘/拖点时滚轮调整高度。地形以下不显示也不允许提交。靠近第一航点（手绘时为飞机出发点）自动闭环吸附，三个以上不同的点可建立循环航路；系统提前续接下一圈，普通右键新航路或清除航点会停止循环。Esc退出设置。

通联字幕直接以无底板文字显示在左侧下方，保留自动淡出及Alt回看；指挥、设置、编队、简报、教学和飞机状态窗口位于字幕上层。拖动窗口标题栏可移动，松开后按窗口分别记住位置，刷新后恢复；窗口不会拖出视口，缩小窗口时自动限制到可见范围。双击标题栏恢复该窗口默认位置，“设置 → 工具与帮助 → 恢复窗口默认位置”可一次复原全部。标题栏获得键盘焦点后也可用方向键微调。

手动添加、追加、拖动、改高度或重绘航点，在安全规划成功并实际生效后，也会由对应飞行员通过现有语音与字幕通联确认；删除、撤销/重做、清空航路同样确认。复诵说明改动的航点、目标高度与剩余点数，沿用当前单位、通联风格、语言和静音设置，不需要指挥AI重新解释。快速连续编辑同一飞机合并为最后一版，校核失败、取消草稿或过时航路不播报“已接收”。

右上方第二行提供常驻“指挥电台”和“任务简报”入口。任务简报显示当前飞机、实际高度速度、航点与机场运行阶段；教学期间入口显示关卡进度，收起后可再次展开。历史教学/考核报告保存在当前浏览器，含分数、四项实飞结果与每关完成记录，可从简报中进入教学并重新练习。宽屏下指挥电台窗口在左、简报或教学在右；窄屏切换查看。

地图顶部常驻罗盘，北向箭头和刻度随观察视角旋转，数值标明“视图朝向”，不冒充飞机航向。教学窄窗口为地图保留独立可见空间，飞机不会被任务卡遮住。

界面默认以地图为主：右上“编队 / 指挥 / 设置”按需切换抽屉，Esc关闭；单位、执行严苛度、出生方式、通联偏好、教学和操作帮助集中在“设置”。底部保留暂停、倍速菜单、时间、航路（空中可用）、视图及通联入口。新通联直接在左侧显示整段列表，播放结束后保留8秒并一起淡出；按住Alt可回看并用滚轮滚动，最近64条记录保留。点击底部通联可固定查看。地图默认只显示选中机航迹、当前/选中航点文字和简洁机场编号，可在设置切回全部显示或隐藏，并记住地图显示偏好。

零基础教程：[进入逐步指挥教学](./training.html)（运行地址 http://127.0.0.1:8000/game/training.html ）。进入实际训练场，选择3个可独立进入、反复练习的大关卡，共52个短步骤：第一关15步教呼号、地面准备通联与单位术语；第二关16步教机位、滑行、跑道许可、起飞、离场交接、巡航与盘旋；第三关21步教航向、实际航点、靶眼、TACAN几何、返场交接和回机位。每屏先认识一个概念，再做一个练习，给出“看哪里”和实际过关反馈。原11课长文保留为[备用手册](./training-reference.html)。

“设置 → 工具与帮助 → 指挥教学”可开启逐步教学或独立挑战。第一、二关从机位开始，第三关从预设空中场景开始；不把空中出生记作玩家完成起飞。开始新关会清空旧的电台草稿，并设置北约通联、航空英制和严格模式。教学与普通游戏统一从“指挥电台”输入文字或语音，原话交给AI理解并下达命令，程序飞行员规划执行，Flash检查并复述。教程不再另设输入框，也不使用课程关键词解析器。示例只填入统一电台，由玩家发送；教官示范同样调用AI。只有实际装订了错误对象、错误跑道、错误目标参数或其他错误飞行任务后才判失败；AI澄清、连接失败和未执行的请求可重试。讲解和过关自动暂停，执行期间可1×/4×/8×观察。独立挑战不展示例，按实际离场、稳定巡航、明确目的点通过、着陆脱离和回机位判定。默认靶眼BAY-REF=[-18000,0,100]米。TACAN两个小关卡只教导航几何，尚无实际调谐接收机。

关卡验证：`node --test tests/training-levels.test.mjs tests/ground-radio.test.mjs tests/control-handoff.test.mjs`，覆盖三大关52步真实地形与物理积分、严苛/宽松交接、独立起点、盘旋过程存档恢复、各落地阶段以及地面通联用语；旧教程进度可继续恢复。

教程验证：`node --test tests/training.test.mjs`，包含真实地图、真实内核的机位→起飞→20000英尺/350节巡航→靶眼090/10海里航点→09L着陆回G1全过程。文本手册由`node tools/export_training_course.mjs`从同一课程内容源生成。

在仓库根目录双击 `start_game.cmd`，或使用以下命令启动游戏及语音指挥 API（需要 Node.js 22.12+）：

```powershell
.\start_game.ps1
```

打开 http://127.0.0.1:8000/game/ 。默认由 Qwen3.7-Flash 担任指挥官，航路点交给程序飞行员执行；每次下令后，飞行员模型（默认 Flash）检查程序返回的结果，再复述。首次启动会生成根目录 `.env`，填入百炼 `DASHSCOPE_API_KEY` 后执行 `.\start_game.ps1 -Restart`。
默认通联播报使用 Inworld TTS-2 Flash。在根目录 `.env` 设置 `INWORLD_API_KEY` 并重启服务；指挥台、塔台、飞行员可分别配置音色。密钥仅保存在服务端，通联文本发送至 Inworld 生成语音；静音不调用合成，取消会停止请求与播放。云端失败时同一句尝试本地语音，设置显示原因并提供“重试Inworld语音”；云端恢复成功即停止本地回退。需要固定使用浏览器本地播报可设置 `TTS_PROVIDER=browser`。完整配置见 [服务说明](../server/README.md#inworld-通联语音)。
默认 `AI_PROVIDER=cloud`：新指令装订后，飞行员模型核对目标设置与采样时刻的实际状态，区分正在执行、已经达到、无法执行和装订不一致，再通过通联字幕与语音复述。持续飞行期间，轻量检查仅在新威胁或持续航路失败时额外唤醒模型；正常飞行不反复推理。判断结束即结束本次模型调用，模型可以选择继续程序飞行，也可以报告缺少数据或能力。人工改令后旧判断作废。当前战术判断与报告不等于已实现接敌或武器执行器。
右侧显示 AI 休眠/唤醒状态。已内置 `data/pilot-handbook/` 简单阅读文件，模型按主题读取。服务固定使用云端模型；本地 2B 实验已停用，不再提供安装或配置步骤。详见 `server/README.md`。
指挥员与飞行员共用本地航空术语词库：2188条公开参考词条的中文简释，另补游戏中的易混含义。每次仅注入本次口令相关内容，涵盖空速/高度、导航、机场通联、编队、接敌简语、传感器、武器通报和应急。阅读规则见[航空术语速查](../data/pilot-handbook/13_航空术语速查.txt)，完整来源与用法见[词库说明](../docs/aviation-terms.txt)。
玩家给任务、目的地或目标，程序生成中间航点。可直接说“Alpha，开始巡航”：沿用已有三维航路；没有航路时保持当前航向与目标高度速度。只有明确要求“沿我画的自定义路线”且路线不存在时，才请求玩家提供路线。已知坐标、地图标记、靶眼、接敌与战术任务不要求玩家逐点画航路；缺失信息和缺失执行能力分别报告。详见 [谁来规划航路](../data/pilot-handbook/12_谁来规划航路.txt)。
普通 Python 静态服务可以展示游戏，但无法提供语音转写和 AI 指令解析。

“设置 → 通用 → 全局单位”默认公制（km/h、m、km），可切换航空英制（kt、ft、NM），设置保存在浏览器。省略单位的指令使用当前设置，明确说出的单位优先；物理状态始终使用SI。马赫数无量纲，两套单位均显示M，数值不变。

右侧语音指挥栏支持点击录音或按住 V 说话，松开 V / 点击结束后转写，最长 20 秒。
默认转写后只填入文字，不自动下令；检查或修改识别文字后，点击“下达指令”或按 Enter 发送，Shift+Enter 换行。需要自动发送时，可在设置中勾选“录音结束后自动下达指令”。
例如“一号机爬升到八千米，速度六百公里每小时”“二号机航向九十度”“全体原地盘旋”“暂停模拟”。
军事口令分“理解意图”和“实际执行”两层。导航、航向、速度、高度、双机集合/跟随/改变队形、掩护/护航伴飞及长僚分工已有执行器；战斗、武器与高级协同等能保留意图，缺少执行器时显示待接入。双机控制支持六种队形，间隔400–5000米；未指定时默认右侧1200米，掩护默认1500米。

可下令“Alpha为长机，Bravo为僚机；Bravo掩护Alpha”“Bravo护航Alpha，保持左侧，间隔1200米”。掩护默认在后上方300米支援，护航默认在侧后上方150米伴飞；长机/受保护机继续原任务。交换长僚可改变实际带队关系，保护机收到独立命令会退出。见[掩护与护航说明](../docs/protection-flight-control.txt)。
可在“设置 → 通联”切换中文通联或北约/ICAO风格，在指挥面板的“口令参考与最近记录”中展开“军事口令手册”查看58类意图与当前能力。试说“Bravo，加入Alpha右梯队，间隔1200米”“全体改为左侧梯队”“Bravo跟随Alpha，间隔1500米”。给僚机独立航路或盘旋命令会退出编队。详见[双机控制说明](../docs/formation-flight-control.txt)。
例如“Alpha，航向两拐洞”会建立可见的西向航路；“二拐跑道起飞后集合”会保留起飞与集合阶段并说明缺失能力。
配置、API 契约、测试与故障处理见 `server/README.md`。

已加入海湾国际机场BAY：双平行3600×45米跑道、23米滑行道、六个机位、航站楼、塔台与灯光标线。左侧底部展开“机场运行”，可观察机场、安排滑行、进入跑道、离场、进近、着陆、复飞或中断起飞。“选中机地面出生”用于场景布置；正常起降没有瞬移。机场阶段和许可会显示在日志中，滑行路线直接显示在地图上。也可说“Alpha，沿A、A1滑行到09L等待点”或“Alpha，09L跑道降落”。
网页默认机位开局，Alpha在G1、Bravo在G2，停车等待指令；“设置 → 场景”可切换“机场机位/空中巡航”并记住选择，重新开始保持该方式。按V说话或使用录音按钮，依次下达：“阿尔法，滑行到零九左跑道外等待。”“阿尔法，零九左跑道起飞，爬升至一千三百米。”“阿尔法，返航本场，在零九左跑道降落。”阶段间无需手工重设飞机位置。最后进近、起飞滑跑、爬升和脱离也显示路线标签。
“设置 → 通用 → 执行严苛度”可选严格模式或放宽模式，默认严格并记住选择。切换不重置飞机，只使尚未装订的旧分析失效。严格模式要求明确平行跑道编号、分阶段下令、按指定滑行路线校验；放宽模式允许Flash补全已有机场/跑道，将滑行、等待、对正和起飞组合成连续离场流程，首选滑行道不可用时可重新规划。补全和改线会显示或播报；两种模式都保留实际碰撞、跑道占用、未知机场/跑道与明确条件的检查。
底部通联区区分“指挥台·玩家”“塔台·BAY”和各机飞行员。塔台阶段许可与飞行员到位/离地/接地/脱离/停车报告按序播放，并保留字幕。收音或解析指令时暂停阶段播报，打开麦克风会停止正在播放的通话，避免把本机播报当成玩家语音。程序飞行持续进行；加速仿真时字幕/语音仍按通话次序播出。
机场采用与等高线沙盘一致的深色地面、建筑和蓝灰轮廓，跑道、滑行道、建筑直接读取机场运行数据的米制位置与尺寸。整平区域内裁去旧等高线与海岸线，避免它们穿过机场模型；分层深度偏移减轻跑道与标线闪烁。跑道在屏幕上的投影长度达到约230像素后开始渐显09L、27R、09R、27L编号，340像素左右完整显示，缩远自动隐藏；地面号码按两端进近方向分别朝向。编号使用固定屏幕字号，不必贴到跑道上才能读清。
滑行道和机位采用相同的暗色标签样式：主滑行道A/B/C随放大先出现，G1–G6机位随后显示，较小的连接道在更近处显示。编号直接取自运行中的滑行图及机位节点，同名滑行道合并，锚点位于实际道路上。标签按跑道、主滑行道、机位、连接道的优先级避让，并避开飞机、呼号和界面面板；放不下时暂时隐藏低优先级编号，偏移较远时加细引线。镜头不变时保留已选偏移，减少反复换位；缩远自动隐藏。
模型负责口令理解和建议，代码负责实体校验、滑行图搜索、占用间隔、起降控制、复飞保护与碰撞。碰撞使用真实米制机体近似体，与远处模型显示放大无关；已接入飞机相撞、机场建筑及机身/翼尖地形接触。机场运行当前为游戏级简化实现，范围、公开依据和代码/模型分工见[机场设计说明](../server/airport-design.md)。

玩家拥有指挥权，AI代指挥台将玩家意图转为命令，电脑飞行员负责复诵、航路规划和操纵。底部通联区按角色显示字幕并使用浏览器本地声音播报，默认开启，可静音或收起字幕。浏览器没有可用声音时明确显示“语音不可用 · 字幕通联”。
任务按“玩家输入→指挥员理解并播报→飞行员处理已播报的通话并规划→程序校验、拟设航点→装订并飞行→检查结果并复述”推进。玩家原文只给指挥员，飞行员不在播报前独立读取原文；持续执行监控也保留实际指挥通话。换算高度按10米或10英尺精度播报，速度取整数，飞行员依照这份近似命令接令，马赫数不变。拟设阶段不修改正式航路；装订前可取消，装订后停止通话不撤销飞行任务。人工改令使旧计划作废。详见[指挥通话与飞行员接令](../docs/commander-pilot-radio.txt)。
复诵、呼号、带单位的参数和无法执行反馈参考公开通联资料；这是一套游戏流程，未声明符合完整的北约或解放军军事条令。详细依据见 `server/military-commands.md`。

视角滚轮以鼠标所指飞机、航点或实际地形为缩放锚点；旋转前按当前可见深度缩短旧观察中心，近景降低旋转和键盘移动速度，松手后停止。空白背景不把近景中心突然拉回远处，缩放距离限制为100米–180公里。航点放置和绘制期间，滚轮继续用于编辑航点，不触发相机缩放。

自动驾驶使用三维视线制导，依据空间转角、速度和剩余距离生成法向加速度需求，再补偿重力得到升力和过载需求。
远距离提前缓转，接近且转角较大时增加过载；最终受机体和当前速度允许的升力限制。界面显示需求 G、可用 G 和当前机动状态。
用户航点是必须依次到达的目标，实际进入250米范围后，还结合出口方向判断切换，在门点附近或出门侧才推进队列；蓝色线是目标连线，绿色线是实际内核预测的安全路径。不会仅因为前视点越过目标就跳过该航点。规划器依据当前航向和转弯半径尝试左右转弯切线、侧向迂回、盘旋取高与地形净空高度剖面，保留各目标的三维位置。提交前用同一气动内核试飞整条路径及到达后的短暂待命阶段，拒绝预测会失速、低于100米净空或飞出地形范围的方案。当前候选均不可行时保留原航路并说明原因，不强行执行危险草稿。
连续多点优先试飞经过各航点的整体曲线：平面夹持三次样条在起点沿实际速度方向，内部航点切线及平面曲率连续；海拔采用单调三次插值，连续爬升不在每个中间点改平，峰顶/谷底逐渐改变爬升方向。曲线仍须通过全程气动和地形检查。已经接近各航点连线长度下界、且没有明显掉速的连续方案直接采用，避免无意义地枚举绕圈。
单点先试飞直接航段；其他候选包含按能量包线计算的多种转弯半径、短S形延长、左右绕山及必要盘旋，不再按固定0.10坡度自动补整圈。候选以实际到达航程为主，在距离相近（约3%）时考虑明显掉速、过载变化和加力使用量，避免为节省很少的路程而大幅减速或急转。搜索是有限候选优化，不保证全局数学最短路径。
高度剖面采用连续三次过渡，转弯前根据未来航段曲率提前减速。正常滚转指令限速约28.6°/秒，增载指令约0.9G/秒、卸载约1.5G/秒，航迹角指令约2°/秒；这些是AI舒适性参数，仍受机体实际响应与安全包线约束。前视点使用协调转弯的曲率关系，避免在弧线外侧反复追点。
制导前视跨越当前及后续两个航段，速度预判覆盖未来约30秒，并按制动距离提前降低速度要求；爬升和过载需求在发动机响应时间之前进入推力预判。前视跨越门点的距离受限，以保留250米到达约束。航点切换保留能量积分器、参考速度、航迹角与滚转/载荷滤波器；最后一个点之后按当时速度方向接入待命圆，避免在终点突然掉头。
飞行中拖动、改高度或追加航点，会在真正开始计算时读取当前位置、速度、滚转、升力、发动机及控制器状态。修改后段优先保留不受影响的前段航路；修改近处目标时，先按当前操纵量积分最多1.8秒的短过渡，再接入连续曲线。候选仍须全程试飞，无法安全衔接时继续比较其他安全路径。提交期间飞机沿原任务飞行，不冻结、不瞬移，也不重置能量或制导状态。
编辑草稿按航点身份跟踪：计算期间已经经过的旧航点会被移除，尚未经过的点保持顺序；正在编辑的目标已经通过时结束该编辑。新草稿取代同机旧草稿，其他飞机的编辑与暂停操作不会无故使本机草稿失效。若结果返回时飞机已沿候选路径前进，只有位置、方向、速度和滚转仍符合接入限制，并通过未来14秒复核时才从前进后的航段接入；否则使用新状态重新计算。滚转物理帧加入0.18秒目标跟随时间常数，消除10 Hz飞控指令带来的阶梯跳动；该时间常数是原型飞控参数。
追加航点回归同时检查物理状态与控制器不重置、实际滚转变化、航点到达顺序和实际航迹长度。覆盖左右转弯、过点前后追加，以及30/60/120 Hz物理步长。2026-11-07复测中，原失败场景按序通过四个航点，追加后实际飞行约26.68公里（规划约26.69公里），60 Hz最大单帧滚转变化约0.59°，未发生失速或额外绕圈；完整86项回归通过。
飞行中每2秒检查未来14秒的轨迹，风险变化时重新规划；暂时无法重新规划则暂停追踪目标并进入安全待命，每10秒重试。正常控制保留临界升力裕度，低能量时优先增速，必要时自动加力。有限候选搜索不能找到所有可能路径；“规划未通过”不等同于该目标在物理上绝对不可达。

`sim/energy.js` 统一管理比能量高度 `h + V²/(2g)`。爬升率和加速参考先限幅、平滑，再由预计机动阻力、势能/动能变化及总能量误差计算所需推力；积分带饱和保护。低于预计载荷安全速度时优先卸载增速；安全速度随 `sqrt(G)` 增长，不再只检查1G失速速度。若最大加力也不能维持目标G，使用未来8秒的速度余量降低机动上限，并限制爬升。
非加力推力覆盖慢车、部分推力与军推，油门按本地Mode0–4非线性模式反算；慢车不等于零推力。所需推力超过军推103%持续0.7秒后允许加力，低于90%持续2秒且已加力3秒后退出，普通重新进入间隔至少1.5秒；安全速度不足或地形紧急时可立即进入。加力量按推力缺口连续分配，再经过发动机时间常数建立。这里的阈值均是可调的原型控制参数。
正常控制与后台预测均使用0.1秒控制步长、1/60秒物理子步长；预测复制能量积分器、加力状态、制导滤波器和已经进入门点范围的证据，避免预览污染真实飞机或在门点之后误判需要掉头。面板显示调推/军推/减推/加力状态，悬停简要状态可查看原因。

航点预览、提交的完整试飞、实时路径预测与后台重规划移到Web Worker，主线程只保留短程复核。提交使用按需创建的第二个Worker，不被预览和实时预测阻塞；同机更新的提交会终止过时的提交计算，队列只保留各通道最新任务。预览首次立即请求，持续拖动时按约140毫秒限频，最多一个在途请求与一个最新草稿，不再等到鼠标停下才计算；旧回包不会覆盖新位置。列表高度修改停止输入300毫秒后异步提交，确认输入时立即提交；输入框按航点编号绑定，队列前移时不会误改其他航点。线条GPU缓冲复用，画布仅尺寸变化时重设，航迹仅采样变化时上传；实时页面不再每帧完整试飞或重建几何。操作菜单底部显示当前FPS及P95帧间隔，具体数值取决于机器和显示器。
拖动位置和高度立柱每帧直接跟随输入，鼠标旁标出海拔及离地高度；底部说明会避开通联栏。琥珀色曲线是即时预估，标注“预计·校核中”；后台完成气动及地形检查后用绿色显示结果。即时预估不用于执行飞行。一次物理帧只处理最新鼠标位置；飞行中保持预览时，按当前状态补充预估并定期刷新后台结果。更新预测时保留上一条完整路径，用固定的三个GPU缓冲交叉淡化，约180毫秒完成主要过渡，不将两条安全路径插值为未经验证的中间路径。提交时预览保留到规划结束，正式预测直接接入提交通过的结果，不清空后等待下一轮预测；取消则淡回原航路。地形以下仍立即隐藏，系统启用减少动态效果时直接切换结果。

真实地形采用本机关卡 LandMesh 导出的1024²高度栅格。目标航点必须至少100米离地；目标之间的直线被山挡住时允许规划安全替代路径。语音指令与鼠标编辑共用检查。实际接触地面时仍按扫掠碰撞判定坠毁；极端初始状态或来不及规避时不会用瞬移、抬高坐标等方式掩盖碰撞。

航路预估不会改动真实飞机。实际超过临界升力后仍会失速降升增阻；意外失速期间卸载、增速并改平，保留目标队列，恢复后重新规划。没有飞行员昏迷机制。

默认两架 F-16A Block 10 以 6500 米海拔空中出生，初始盘旋待命；完成航点后在终点附近盘旋。采用机身、机翼、水平尾翼、垂尾、座舱和喷口组成的简单三维模型；机背/机腹明暗区分，翼尖保留编队颜色，加力显示尾焰。姿态直接来自飞行内核。远景模型便于辨认，近景逐渐恢复正常比例。
三维质点气动采用升力、抛物线阻力、随高度/速度插值的推力、重力与有限滚转/升力响应。
姿态由速度、升力方向和迎角构造。速度指令范围400–2400千米/小时，自动驾驶还受本机型IAS/Mach限制。

`data/aircraft.json` 保存有效性能：默认 F-16 的机翼几何、升力参数及推力表来自本地 `f_16a_block_10.blkx`，原 F-86 配置仍可复用。
F-16 使用原型选定的固定10000千克飞行质量、整机 CD0=.020、正常9G上限、120°/秒滚转响应及1.2/秒升力系数响应。推力基值按kgf换算牛顿；7×12高度/真空速表、`ThrAftMaxCoeff`、Mode4/5推力倍率、加力倍率与发动机时间常数来自本地FM。非加力/加力推力按实际加力建立量连续混合；需求超过非加力能力时自动启用，恢复后退出，带滞回避免频繁切换。尚未模拟燃油消耗与发动机进气细节。
`MachCrit/Max/MultMachMax/MultLineCoeff/MultLimit` 的1/2/3/5组用于阻力、升力斜率、临界升力和临界迎角的有效修正；机翼与机身的阻力增量均使用已有配置。临界点到峰值用三次曲线连接，峰值后平滑延续配置斜率，跨M1没有硬切换。标准大气分对流层/等温层计算密度和当地音速。
这些马赫数因子的含义及组合是本原型的简化解释，未获得战争雷霆私有求解器，因此不能视为完整复刻原游戏的跨音速包线。声速与波阻的一般物理依据见 [NASA：Mach数的作用](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/role-of-the-mach-number/) 和 [NASA：影响阻力的因素](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/factors-that-affect-drag/)。
