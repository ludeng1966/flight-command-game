雷达 v2 实战联调记录（2026-11-12）

结论
同信道友机态势共享正常；真实模型能够修改三维搜索策略，并能请求截获、形成实际锁定。
接敌闭环未通过：五轮均没有蓝方发射，最后一轮仍反复锁定和选弹。不能认定 AI 已能可靠自主作战。
实际告警能触发本地程序规避，模型随后能复核；尚不能证明模型的规避比本地规则更有效。
小场景传感器 p95 低于 2ms，但整局仍有秒级同步机动规划阻塞，不能称为全程无卡顿。

测试口径
直接运行游戏 World、RadarPilot、AttackPilot、RwrPilot、导弹、雷达 v2、数据链和实际 HTTP 模型接口。
健康接口返回模型 qwen3.7-flash；不是模拟模型，也不是本地 2B。模型只获得己方状态及传感器/通信观测。
蓝方两架 F-16 使用真实云端 Flash，红方一架 F-16 使用依据自身观测行动的本地规则对手。
接敌授权由测试程序通过现有结构化任务接口下达，没有测试玩家语音识别、指挥员自然语言规划或语音合成。
固定传感器种子 41，平坦无地形；配置 1 倍速、60Hz 物理、20Hz 传感器。等待模型时仿真继续推进。
云端生成仍有随机性，各轮时长/提示有所不同，字段修复前后不是严格同条件统计 A/B。
火控对照组关闭红方雷达和武器，红方不主动反击；它用于定位闭环错误，不代表真实对抗胜率。
运行环境：i9-13900HX，Node v24.22.1。无浏览器渲染/GPU负载，不能据此判断整机帧率或显存。

搜索与接敌证据
1. 基线雷达响应因模型填入当前动作不使用的字段而失败；飞行参数不合法、过期目标另行被校验拒绝。
2. 增加 normalizeRadarProposal，仅清空当前动作不用的已知字段，保留原始模型输出和归一化记录。
   不推测目标、不转换或截断实际使用的航向/高度/速度，不绕过观测时效和火控约束。
3. 45 秒搜索复测真实执行了 scan，记录“三维扫描策略已装订，覆盖以实际波束为准”；13 次请求无 HTTP 错误。
4. 基线接敌模型混淆“允许尝试截获”和“已有火控”，多次选弹却没有请求锁定。
   在模型可读卡片中明确 acquisition=true 允许请求 radar_lock，fireControl 在实际跟踪后建立。
5. 最后复测 ALPHA 在 48.867 秒请求 radar_lock，50.917 秒实际进入截获，52.100 秒形成锁定；
   52.467 秒请求时 weapons.ready=true，但本任务未完成 select，模型按现有协议先选弹。
   该响应用时 3052.424ms，到 55.500 秒执行；实际锁定已于 54.000 秒丢失，首个锁定窗口仅 1.900 秒。
   这次选弹本身符合协议，失败同时涉及串行协议耗时和火控持续性，不能全部归因于模型不会开火。
   74.800 秒再次实际锁定；75.183 秒已选相同型号/目标，武器提示超出截获角，模型却再次 select。
   此响应约 2505.786ms，77.683 秒执行，77.700 秒又丢波；没有选择改善截获角或支持几何。
   模型重复 radar_lock/select，部分时候航迹又老化，90 秒内没有发射。
   这是可定位的协议/决策/时效问题，不能用“接口成功”代替“战术正确”。
6. 最后复测 HTTP 均成功，但 BRAVO 一次 wait 被客户端世界校验拒绝：持续无回波时不能无限等待。
   因而 HTTP 错误为零不等于所有决策执行成功。
7. 各轮没有蓝方发射。三个有反击的场景各发生一次红方 AIM-120 发射，无命中；全部飞机存活。
   未命中和存活不构成蓝方模型规避有效或具备优势的证据。

告警与规避证据
原始搜索场景 BRAVO 于 9.800 秒、ALPHA 于 9.850 秒收到 track/launch 级告警并进入本地程序防御。
原始交叉场景 BRAVO 于 3.150 秒告警并进入本地程序防御；敌方于 5.683 秒实际发射。
上述首次动作来源是 program_local_rule，不是模型在同一帧完成推理。
前三轮分别记录 6/3/4 个本地防御片段及 4/3/3 次模型复核；模型会输出维持或调整 notch 等判断。
模型对搜索级告警/发射确认的表述仍需检查，不能将其通话描述当作已验证威胁身份。
缺少关闭模型复核的相同条件对照及更多种子，尚不能量化规避增益。

性能与剩余阻塞
雷达+RWR 统计仅包括传感器实际到期的 20Hz 步，不把空闲物理帧混入分位数。
五轮传感器 p95 为 0.191—0.758ms；基线最坏单步 24.863ms，复测三轮最坏为 1.944/2.226/1.583ms。
2ms 的 p95 在这个三机场景中达到；严格每步 <=2ms 未达到，大规模编队也未由这次实战验证。
World.step p95 为 0.460—1.269ms，但基线最长 2981.727ms。
新增机动计时后，attackManeuver 同步耗时在搜索复测/火控对照/最终复测分别最长
2887.815/3159.797/2505.724ms；这类回调可能发生在 World.step 外，不能仅查看 world.step 的 p95。
阻塞路径为 attackManeuver -> applyPlan -> preparePilotPlan/planSafeRoute；搜索复测观察到约 2.563 秒循环落后。
异步等待云端响应没有主动暂停世界，但同步装订/安全航路求解仍会阻塞事件循环。
优先应把此段规划改为后台或分段执行，并给结果加任务版本/执行时效检查；本次未改动整个导航架构。
决策侧需要减少重复选弹/重复截获，在请求前明确当前 ready、已选弹和任务阶段；执行前仍必须复核火控。
协议侧可把有依据的选弹准备前置，减少锁定窗口内串行等待，并表达有时效/条件的持续意图；
是否真正发射仍由已有授权、执行时火控及武器条件裁定，不以过期快照或缓存 ready 代替校验。
