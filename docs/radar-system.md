# 简化机载雷达与锁定

## 已实现的流程

F-16 使用本项目的简化搜索雷达。F-86 当前未配置搜索雷达。参数是游戏设定，未标注成真实型号的完整性能。

通过界面顶部“雷达”按钮观察状态。玩家只下达任务，雷达模式与目标截获由飞行员模型自主判断：

- “Alpha，搜索前方空域。”
- “Alpha，持续跟踪前方不明目标。”
- “Alpha，持续跟踪 TGT 01。”（暂未发现时先搜索）
- “Alpha，关闭雷达，保持电磁静默。”

语音识别继续走现有百炼 ASR 和 Flash 指令解析。模型接收任务，自主选择工作模式与要截获的本机航迹，并在掉锁后重新判断；发现、截获、失锁由模拟代码根据每次更新的几何关系判断。面板不提供手动模式或锁定按钮。雷达命令不改航向、航点、速度或编队任务，也不授予开火许可。

## 速度门的具体定义

设由雷达指向目标的单位视线为 `LOS`，载机速度为 `V_own`，目标速度为 `V_target`。以下均使用 ENU 世界坐标和 m/s。

```text
目标闭合率       = (V_own - V_target) · LOS
静止地面闭合率   = V_own · LOS
目标与杂波速度差 = -V_target · LOS
```

本游戏默认杂波速度门**半宽**为 80 m/s：有主瓣地面杂波时，若目标与杂波速度差的绝对值小于 80 m/s，PD 模式滤除该回波。等于边界时可通过。该数值可在 `sim/radar.js` 的 `RADAR_DEFAULTS.speedGateHalfWidthMps` 或飞机 profile 的 `radar` 配置中调整。

因此目标横切时，即使与载机的闭合率很高，也可能进入杂波门；不能只比较双方空速差。明确上视、主瓣不触及地面时，本版本不套用这个地面杂波门。地面杂波判断使用目标方向、波束半角、载机离地高度及等效地球曲率。SRC 模式不使用速度门，但主瓣有地面杂波时直接按遮蔽处理。

80 m/s 是本项目指定的简化参数，不能称为所有真实雷达的固定门宽。真实滤波还涉及 PRF、波形、旁瓣、距离模糊及处理算法，本版本尚未模拟这些因素。

## 状态与时间

| 设置 | 当前游戏参数 |
| --- | --- |
| 探测范围 | 150 m 至 60 km |
| 天线范围 | 机体坐标方位 ±60°、俯仰 ±30° |
| 扇区扫描周期 | 2 s，简化水平扫掠，不模拟完整多条栅格扫描 |
| 传感器更新 | 20 Hz，使用模拟时钟，暂停时停止 |
| 截获等待 | 连续有效回波 0.8 s |
| 短时航迹记忆 | 1.5 s，随后掉锁并恢复搜索 |
| 搜索航迹保留 | 最后观测后最多 4 s |

还检查目标存活、距离、天线角度、等效地球曲率视距和地形栅格遮挡。地形视线检查不用导航的 100 m 安全余量。扫描外的目标不会直接变成已探测航迹。单目标跟踪期间停止搜索其他目标。

丢波立即停止有效雷达支持，航迹仅按最后观测位置和速度线性外推。外推期间不更新为目标的真实新位置；短时恢复回波可恢复跟踪，超过记忆期则掉锁。“开始截获”回执不等于“已锁定”，实际锁定、掉锁另有飞行员通联事件。雷达航迹仅区分友机和未识别，不因出现在雷达上就判为敌机。

`unit.radar.canIlluminate` 是半主动制导可读取的游戏支持状态，只在有有效锁定回波时为真；它不是已实现真实连续波照射器的声明。自主雷达任务不自动发射武器，搜索、跟踪和开火授权分别处理。

## 演练与显示

飞机在空中时，打开“雷达演练”，添加前方练习靶。靶机是匀速脚本目标，用于重复测试迎头与横切关系，不是具备完整飞控和实体碰撞的战斗单位。下达搜索或跟踪任务后，由模型自主开机并截获；点击“靶机横切”可观察外推和掉锁，“靶机迎头”可恢复有效回波。最多同时四架；清除后新靶使用新的 ID。

雷达屏显示测得的方位、距离、闭合率、杂波速度差和回波年龄。灰色航迹为外推。三维地图连接当前选中飞机与其截获/跟踪航迹，丢波时连接外推位置。雷达状态、事件游标所需序号及练习靶可随自动存档恢复；旧存档缺少雷达字段时默认关闭。

## 模型操作闭环

`search` 与 `track_target` 编译为独立 `sensor_task`，不改变原航路或编队。任务开始、新航迹和丢波时，`POST /api/tactical/pilot/radar` 调用已配置的飞行员模型，只提供本机姿态、任务及雷达已观测航迹，不提供其他目标的隐藏真值。模型每次决定一项操作，程序在最新状态上核验后执行。稳定锁定不重复请求；持续搜索无变化时每20模拟秒复核一次。新任务、静默、暂停、换局或模型切换会作废旧请求，错误不会伪装成已执行。

操作原因和真实结果写入雷达过程列表与飞行员电台；截获等待不等于锁定成功，掉锁另行通报。自主任务随进度保存，恢复时重新启动已中断的判断。演练靶机生成只改变场景，不再暗中打开雷达。

## 文件

- `sim/radar.js`：几何、可见性、扫描、跟踪状态、口令校验、模型可见上下文。
- `sim/world.js`：物理循环接入、雷达操作、练习靶。
- `sim/radar-task.js`：任务、事件门控与最新状态操作核验。
- `server/radar-pilot.mjs`：模型判断接口与观测隔离。
- `game/radar-pilot.js`：持续任务判断与过期请求处理。
- `game/radar-control.js` / `game/radar.css`：雷达屏和操作。
- `game/radar-radio.js`：飞行员事件通联，复用现有语音播报。
- `three3d/radar-scene.js`：练习靶和跟踪连线。
- `tests/radar.test.mjs`：速度门、边界、上/下视、遮挡、截获/掉锁、原子执行、通联和存档测试。

机制参考：[War Thunder 官方 Wiki：Airborne radars](https://wiki.warthunder.com/mechanics/198-airborne-radars)。参考其模式与杂波关系；没有复制或声称复现其闭源雷达求解器。
