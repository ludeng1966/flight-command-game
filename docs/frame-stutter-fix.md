# 主线程卡顿修复（2026-11-11）

定期航路复查原本每两秒在 `World.step` 内同步积分未来 14 秒飞行；多机与倍速会集中触发。浏览器现在把相同的检查交给已有规划 Worker，检查不通过才重规划。等待时沿当前航路飞行，原有实时飞控、地形碰撞与过期结果校验继续生效。无 Worker 的离线仿真保留同步检查。

物理补算原本会在一次动画回调内清空积压；某帧变慢后，下帧补算更多，形成持续卡顿。现在保持 1/60 秒物理步长，单次补算约 6 ms 后让出主线程，并限制积压。性能长期不足时仿真时间会慢于所选倍速，不通过放大物理步长强行追赶。暂停、重开会清空积压。

点击和表单变更不再立即重复编码、写入整份存档，改为合并到空闲回调。定期保存继续生效，关闭、刷新、切后台仍同步保存最终状态。渲染在写标签样式之前缓存画布尺寸，避免每个标签都读取布局；航点标签高度与视口高度分开，修复原有变量遮蔽。

验证：`node --test tests/frame-budget.test.mjs tests/autosave.test.mjs`；离线调度对比：`node tools/benchmark-frame-budget.mjs`。此基准只测 CPU 调度，不代表实际浏览器 FPS。实际界面检查被用户手动停止，尚未取得修复后的浏览器帧率测量。
