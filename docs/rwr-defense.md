# 雷达告警与玩家优先的自卫

## 研究依据

[战雷官方 RWR 机制说明（2023-09-13）](https://warthunder.com/en/devblog/current/8466)说明：接收频段、跟踪识别和发射识别因设备而异；先进设备可持续保留辐射源，部分设备能从照射通道或制导信号识别发射。这个说明是机制参考，不把当年的设备表称为永久不变的现行全表。

2026-11-08 另读取本机安装包的 `gamedata/sensors/us_an_alr_56m.blk`，F-16 本地载机配置确实引用它。本机配置为 70 km 参考范围、5 s 信号保留、最多12个跟踪源；`detectTracking=true`。根层 `detectLaunch=false`，但46个信号分组单独允许发射识别，包含F-16雷达族与ARH。不能只读根开关就断言完全不支持发射告警，也不能反过来给所有波形全能发射告警。

`data/rwr-reference.js` 保留所选源参数、信号分组及源文件 SHA256。复核和再生成命令：

```powershell
F:/mygame/wt_flight_research/tools/unpacker/wt_ext_cli.exe unpack_vromf -i 'D:/steam/steamapps/common/War Thunder/aces.vromfs.bin' -o .game-server/rwr-source --folder gamedata/sensors/us_an_alr_56m.blk --format Json --blk_extension blkx --no_dump_nm
node tools/import-rwr-reference.mjs
```

## 简化映射

F-16 默认配备简化RWR，F-86默认没有。接收在20 Hz运行，使用实际辐射源和视线几何，不直接把“世界里有敌方导弹”当成告警。

| 可观察信号 | 游戏内判断 |
| --- | --- |
| 开启雷达但扫描波束尚未扫到本机 | 不产生该次接收 |
| 搜索波束照到本机 | 搜索辐射，只报告 |
| 持续跟踪波束照到本机 | 跟踪告警 |
| 支持在空半主动弹的有效照射 | 对已识别的简化战斗机信号类给出疑似发射告警 |
| 主动雷达弹开机、波束覆盖本机 | 主动导引头/疑似发射告警 |
| 主动弹尚未开机或红外被动寻的 | 不凭弹体存在产生RWR发射告警 |

接收还受源频率、接收机覆盖、距离和地形遮挡限制。当前把现代简化接收机设为2–20 GHz、上下±45°，方位以15°档近似，最多12源、5秒保留。频率区间、波束与识别类映射是本项目游戏设定，没有复刻完整战雷信号库。参考源虽有友敌识别字段，本项目未实现RWR身份鉴别，故告警不自行标成敌机。

雷达因为目标横切而丢失回波，不代表发射机立刻停发，也不代表RWR一定静默。横切只尝试在适用的PD下视情形进入杂波速度门，不会降低发射功率。具体雷达和导引头是否失锁仍由既有传感器物理判断。

## 处置流程

接收告警 → 立即在“告警”面板显示 → 通联空闲时报告 → 等待玩家指令 → 没有新指令才自主机动。

- 默认持续跟踪等待 **8秒**，疑似发射等待 **4秒**；均为模拟时间，可调1–30秒，暂停时不推进。
- 搜索照射不触发自主转向。新源、告警升级以及同一源再次出现独立发射信号，可重新报告并开启等待。
- 同一轮告警中，玩家成功下达新指令会取消当前等待或停止自主机动，执行玩家任务；不会在几秒后又抢回控制。玩家录音、发送或等待指令解析时，尚未开始的规避等待暂缓；已经在飞的机动持续至新指令成功装订，再交还控制。未发送的文字草稿不算新指令。
- “只报告”模式持续生效，仍接收、显示和报告告警，不因等待超时改变航向。
- 默认横切，模型可以按实际观测建议横切或背向脱离。模型慢或服务失败时，本地有限规则继续运行，不让飞行停住；没有相关告警时不请求这个模型判断。

模型只收到本机遥测、近似方位、信号等级与时间，不收到隐藏辐射源ID、坐标、距离、对方速度或精确命中剩余时间。模型建议只应用于仍有效的同一轮告警，控制序号和玩家接管状态会拒绝旧回复。已接管或只报告时不调用告警判断模型。

## 飞行与任务保护

规避经现有气动飞控真实转弯，保留原航点、原任务目标及推力约束，不瞬移、不删除任务，也不自动开火。规避时暂停原航路的到点计数与后台重规划，结束后从实际位置重新校核并接回。

地形前视同时检查当前运动方向和规避方向。失速改出优先；地面、最后进近和低于300米净空的初始离场不由自主规避接管。任何动作都不保证成功躲过导弹。

信号消失只表示暂时不再收到该辐射，报告不会声称导弹已失效或已被击败。尚未加入箔条、热焰弹、干扰机、完整功率/脉冲参数估计及完整威胁库。

## 操作和接口

刷新游戏后点顶部“告警”。面板显示相对钟点方位、搜索/跟踪/发射等级、处置状态和可调等待时间。圆环按告警等级分层，不表示距离。静音只影响声音，接收和处置继续运行。

可用口令：

- “Alpha，告警只报告，不要自主规避。” → `defend / report_only`
- “Alpha，恢复自主规避。” → `defend / auto`
- “Alpha，立即向左规避。” → `defend / execute / left`
- “Alpha，NOTCH RIGHT。” → 明确横切
- “Alpha，航向270度，DRAG。” → 按指定航向脱离

玩家口令继续先由指挥员播报，飞行员只接收实际通话。执行结果会核对策略/机动装订，不把“开始规避”当成“已安全”。

演练按钮产生120秒定向辐射源，用于检查流程；明确不生成导弹。真实雷达和在空主动/半主动弹也接入同一接收机制。清除演练源后信号仍会按接收记忆短暂保留。

- `sim/rwr.js`：接收与观测；`sim/rwr-defense.js`：处置策略与控制优先级。
- `POST /api/tactical/pilot/rwr`：事件驱动的Flash建议，正常无告警不调用。
- `game/rwr-radio.js`：现有通联队列中的告警报告；忙碌后只报告仍有效的状态。
- 策略、等待、告警历史、控制序号及玩家接管状态随现有存档恢复，旧存档自动补默认接收机。

验证：`node --test tests/rwr.test.mjs`；真实服务链路报告保存在本机忽略目录 `.game-server/rwr-live-command.json`。
