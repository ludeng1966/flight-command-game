# 飞行员自主攻击任务

玩家只需下达“Alpha，攻击前方目标”或“Alpha，攻击 TGT 01”。无需先选雷达模式、手工锁定、选择导弹或点击发射。武器面板改为观察界面，接收任务后自动打开，显示实际挂载、当前选择、导引头状态、操作记录与在空导弹实时数据。飞行员判断和真实结果沿用现有电台字幕与语音设置。

## 执行闭环

`attack` 编译为持续的 `attack_task`。模型每次决定一个动作：雷达模式、截获、选弹并装订目标、等待、发射、必要的攻击飞行或中止。无回波时先搜索，不把未知目标编号当作要求玩家手动操作的理由。默认挂载不代表飞行员已选弹：每个攻击任务必须先有一次模型选弹决定，才允许自动发射。

模型通过 `/api/tactical/pilot/attack` 获取本机状态、雷达/光学已观测航迹、可用导弹资料、当前物理发射检查及本任务导弹遥测。不提供其他飞机或目标的隐藏位置。目标第一次由模型明确选择后绑定任务，不能改打其他目标；玩家点名的目标和明确的武器、飞行数值须保留。已识别友机禁止攻击。

默认盘旋中接到前方攻击任务时，模型可先沿接令时的本机航向建立搜索航段，自主选择高度和速度。未发现目标时该操作不填目标编号，也不获取隐藏目标坐标；航点通过现有地形和飞行可行性检查，飞机沿正常飞控逐步执行，玩家能看到航路变化。

模型的发射决定不是直接生成命中结果。执行前再次验证本机挂载、实际导引头准备、雷达跟踪、目标截获角/可见性、余弹、任务额度及最新任务身份。检查失败不扣弹、不生成实体，把原因交回模型修正。通过后沿用 `spawnMissile` 和 `stepMissiles` 的实时推力、质量、阻力、制导与碰撞计算。

半主动弹需要持续雷达支持；主动弹进入自主段前须维持必要支持，红外弹使用实际光学/导引头条件。发射后模型观察在空状态，不连续重复发射；任务默认最多两枚，模型可只用一枚，也可根据实际脱靶结果决定补射。玩家明确数量时作为本任务发射额度，不能超额；既有直接“发射两枚”的兼容命令仍按原数量执行。

任务完成只由本任务导弹实际命中指定对象的物理结果确认。寿命结束、超航程、失去制导或触地不算命中；额度用完仍未确认摧毁时如实报告。停止任务不能召回已在空导弹，后续真实结果仍会记录。

## 生命周期

武器保持/停止射击、换任务、暂停、换局或模型切换，会取消或作废旧判断，不能由迟到回复再次发射。攻击任务、已发射实体、余弹和结果一起保存；恢复时重新判断已中断的模型请求。地面接收的任务等待离地，不在机位发射。

雷达搜索或持续跟踪任务本身没有攻击授权；只有已接收的攻击任务能调用自主武器执行。混合挂载和补弹仍属于折叠的演练场景配置，不代替飞行员在任务中的实际选弹，也不表示这些型号都符合真实载机挂载。

## 文件

- `sim/attack-task.js`：授权任务、状态、观测、逐步动作校验及结果监视。
- `server/attack-pilot.mjs`：Flash 判断、结构化操作和观测隔离。
- `game/attack-pilot.js`：持续执行、过期请求与模型重试。
- `game/weapon-control.js`：只读攻击观察界面和演练场景配置。
- `tests/attack-autonomy.test.mjs`：授权、准备、发射、任务替换、结果、存档和模型接口测试。

本功能使用本游戏现有简化传感器和导弹模型，不声称复现真实武器系统或战雷闭源求解器。
